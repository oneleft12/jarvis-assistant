# Отчёт: Админ-панель J.A.R.V.I.S. с PIN-кодом

**Проект:** J.A.R.V.I.S. — Windows voice-assistant (https://windowshelper.win)
**Версия:** v2.8
**Дата:** текущая ревизия репозитория (ветка `main`)

---

## 1. Введение

Проект J.A.R.V.I.S. — веб-интерфейс-«голо-ХАД» персонального помощника: чат с ИИ, терминал,
игры, мониторинг системы, управление ПК. Сайт опубликован через Cloudflare Named Tunnel под
доменом `windowshelper.win`, поэтому им пользуются не только владелец, но и посетители («гости»).

До появления админ-панели управление сервером требовало правки кода и перезапуска «руками»,
а любой владелец сайтового PIN-кода (1212 он же известен друзьям) фактически имел доступ ко
всем функциям API. Требовался слой администрирования.

**Цель работы:** спроектировать и реализовать админ-панель с PIN-доступом, включающую:

1. отключение сайта **для других пользователей** (посетителей) без потери собственного доступа;
2. смену PIN-кода самого сайта (и отдельно — админ-PIN-кода);
3. прочие функции, необходимые полноценной админ-панели.

## 2. Поставленные задачи

| № | Задача | Статус |
|---|--------|--------|
| 1 | Отдельный админ-PIN и вход в панель с rate-limit | Готово |
| 2 | Отключение сайта для посетителей (503) с сохранением доступа админа | Готово |
| 3 | Смена сайтового PIN-кода из панели (без перезапуска) | Готово |
| 4 | Смена админ-PIN-кода (с подтверждением текущим) | Готово |
| 5 | Экран «офлайн» у посетителей при выключенном сайте | Готово |
| 6 | Режим «гостям вход закрыт» (403 через домен) | Готово |
| 7 | Выключатель ИИ-чата | Готово |
| 8 | Очистка журнала / памяти / таблиц рекордов | Готово |
| 9 | Рассылка системного сообщения всем клиентам | Готово |
| 10 | Перезапуск сервера из панели | Готово |

## 3. Архитектура и модель доступа

Три уровня доступа, различаемых сервером по HTTP-заголовкам и Host:

```
                 ┌──────────────────────────────────────────────┐
   посетитель    │  Host: windowshelper.win (туннель Cloudflare) │
   (друг)        │  x-jarvis-pin = 1212  → обычный доступ       │
                 │  без PIN → 401    сайт выкл → 503            │
                 │  гости выкл → 403                             │
                 ├──────────────────────────────────────────────┤
   владелец      │  Host: localhost:3000                         │
   (локально)    │  x-jarvis-pin = сайтовый PIN                 │
                 ├──────────────────────────────────────────────┤
   администратор │  x-jarvis-admin = токен из /api/admin/login  │
                 │  проходит ВСЁ, в т.ч. при выключенном сайте  │
                 └──────────────────────────────────────────────┘
```

**Порядок проверок в гейте `server.js` (iddleware на `/api/*`):**

1. валидный админ-токен → пропустить;
2. путь `/api/admin/login` → пропустить (иначе при выключенном сайте нельзя войти, чтобы
   включить его обратно; защита — rate-limit внутри роута);
3. `siteEnabled === false` → **503** `site_disabled` + текст из панели;
4. `guestsAllowed === false` и запрос извне (`Host ≠ localhost`) → **403** `guests_disabled`;
5. `/api/auth` → пропустить (свой rate-limit);
6. заголовок `x-jarvis-pin` равен сайтовому PIN → пропустить, иначе **401**.

Ключевое свойство: **админ-токен независим от сайтового PIN**. Смена сайтового PIN не
разлогинивает админа, отключение сайта не закрывает панель.

## 4. Функции админ-панели

| Функция | Как работает | Эффект |
|---------|--------------|--------|
| **Вход** | Админ-PIN (дефолт `9111`) → `POST /api/admin/login` → токен 48 hex, хранится в `sessionStorage` | 5 неудач подряд **с одного IP** → блок этого адреса на 60 с (не всех посетителей); токен живёт до перезапуска сервера |
| **Сводка** | `GET /api/admin/status` | Сайт/гости/ИИ, аптайм, версия, размер журнала и памяти, **маскированные** PIN-ы (`•••2`) |
| **Отключение сайта** | Флажок + текст сообщения → `POST /api/admin/site` | Посетители получают 503 и экран «ОФЛАЙН» со *своим* текстом; админ продолжает работать |
| **Смена PIN сайта** | Поле 4–8 цифр → `POST /api/admin/pins {sitePin}` | Эффект мгновенный; клиенту админа новый PIN подставляется сам; у остальных старый перестаёт работать (401 → оверлей) |
| **Смена админ-PIN** | Текущий + новый → `POST /api/admin/pins {currentAdminPin, adminPin}` | Текущий обязателен — одного токена недостаточно |
| **Гости** | Флажок → `POST /api/admin/guests` | Выкл → через домен все API отвечают 403, локально работает как раньше |
| **ИИ-чат** | Флажок → `POST /api/admin/ai` | `JARVIS_AI=off/on` читается живьём: без ИИ чат переходит на заготовленные фразы |
| **Очистка** | Кнопки Журнал/Память/Рекорды → `POST /api/admin/clear` | `data/memory.json`, `data/scores.json`, журнал в памяти |
| **Рассылка** | Текст → `POST /api/admin/broadcast` | Клиенты подхватывают её вместе с метриками `/api/system` (уже опрашиваются каждые 2 с) и показывают в чате (`📣`) и терминале |
| **Перезапуск** | Кнопка → `POST /api/admin/restart` | Поднимает новый `node server.js` (detached) и завершает старый; панель сама ловит сервер и просит войти заново |
| **Выход** | Кнопка → `POST /api/admin/logout` | Токен сгорает на сервере |

**Вход в панель (три способа):** ссылка `▸ админ` на PIN-оверлее, кнопка на экране «ОФЛАЙН»,
горячая клавиша **Ctrl+Shift+A** (работает и в русской раскладке).

## 5. Техническая реализация

### 5.1 Файлы

| Файл | Роль |
|------|------|
| `services/adminStore.js` | Настройки в `data/admin.json` (gitignore), набор живых токенов |
| `routes/admin.js` | 10 эндпоинтов панели + rate-limit входа + перезапуск |
| `server.js` | Гейт: токен → login-exempt → 503 → 403 → PIN |
| `routes/system.js` | `/api/system` отдаёт `broadcast` |
| `services/aiBrain.js` | `JARVIS_AI` проверяется живьём в `ask()` |
| `services/memoryStore.js`, `services/scoreStore.js` | `clear()` для очистки из панели |
| `index.html` | Оверлеи «ОФЛАЙН» и «АДМИН», fetch-обёртка (подставляет оба заголовка, ловит 503/403), JS панели, приём рассылки |

### 5.2 API админ-панели

```
POST /api/admin/login    {pin}                 → {ok, token, cfg} | 401 | 429
GET  /api/admin/status                         → {siteEnabled, guestsAllowed, aiEnabled,
                                                 sitePinMasked, adminPinMasked, maintenanceMsg,
                                                 uptime, version, logs, memory, tokens}
POST /api/admin/site     {enabled, message}    → {ok, cfg}
POST /api/admin/pins     {sitePin?, adminPin?, currentAdminPin?} → {ok, cfg} | 400 | 401
POST /api/admin/guests   {allowed}             → {ok, cfg}
POST /api/admin/ai       {enabled}             → {ok, aiEnabled}
POST /api/admin/clear    {what: logs|memory|scores} → {ok} | 400
POST /api/admin/broadcast {text}               → {ok} | 400
POST /api/admin/restart                        → {ok} (новый процесс, старый уходит)
POST /api/admin/logout                         → {ok}
```

Все эндпоинты, кроме `login`, требуют заголовок `x-jarvis-admin` (403 без него) — **даже при
наличии сайтового PIN**.

### 5.3 Фронтенд

* `window.fetch` переопределён один раз: к каждому `/api/*` запросу подставляются
  `x-jarvis-pin` и `x-jarvis-admin` из `sessionStorage`;
* ответ **503** читается через `resp.clone()` и открывает экран «ОФЛАЙН» с текстом из панели
  (админу с валидным токеном этот экран не показывается);
* ответ **403** `guests_disabled` — тот же экран; `admin_token_required` — сброс токена и
  возврат к форме входа;
* флажок «сайт» в панели применяется по кнопке СОХРАНИТЬ (с `confirm` при выключении).

## 6. Информационная безопасность

| Угроза | Мера |
|--------|------|
| Подбор сайтового PIN | Rate-limit **на IP**: 10 неудач → 60 с (реальный IP берётся из `CF-Connecting-IP`, который edge всегда перезаписывает — подделать нельзя); PIN 4–8 цифр (после смены) |
| Подбор админ-PIN | Отдельный PIN, rate-limit на IP 5/60 с, ответ 429 с текстом; спам одного адреса не блокирует остальных |
| Чтение PIN-ов из репозитория | `data/admin.json` в `.gitignore`; в API-ответах PIN **маскируются** |
| Злоумышленник с сайтовым PIN меняет/выключает | Админ-эндпоинты требуют свой токен — сайтового PIN мало |
| Гость «выключает» чужой сайт | Панель не отдаётся без админ-PIN; гостевые ПК-действия и так изолированы (гостевой режим) |
| Кража токена из `sessionStorage` | Токен живёт до перезапуска сервера, действует только на `/api/admin/*`, можно погасить кнопкой ВЫЙТИ и перезапуском |
| Отключение «с собой» (само-локдаун) | `/api/admin/login` exempt от 503 — вход в панель доступен всегда |
| Остаточная уязвимость | Восстановление `data/admin.json` даёт прежний PIN (см. §9) |

## 7. Протокол тестов

1. Синтаксис: `node --check` для `server.js`, `routes/admin.js`, `services/*.js`, извлечённого
   JS из `index.html` — OK.
2. PIN-гейт: `GET /api/state` без заголовка → 401; с `x-jarvis-pin: 1212` → 200.
3. Вход админа: неверный PIN → 401; верный → токен; `status` без токена → 403.
4. **Отключение сайта:** `site {enabled:false}` → `GET /api/state` с сайтовым PIN → **503**
   `site_disabled`; с админ-токеном → **200**; `POST /api/auth` посетителю → 503. Включение
   обратно → 200.
5. **Смена PIN сайта:** `pins {sitePin:9999}` → старый PIN → 401, новый → 200; возврат `1212`.
6. **Смена админ-PIN:** неверный текущий → 401; верный → смена, повторный вход новым PIN →
   ок; возврат `9111`.
7. Гости: `guests {allowed:false}` → запрос с `Host: windowshelper.win` → 403, `localhost` →
   200; возврат включено.
8. ИИ: `ai {enabled:false}` → чат отвечает заготовкой (без обращения к 9router); включить обратно.
9. Рассылка: `broadcast {text}` → `/api/system` содержит `broadcast.id`; клиент показывает 📣.
10. Очистка: `clear {what:logs}` → журнал пуст (кроме самой записи об очистке).
11. Перезапуск: `restart` → порт 3000 поднимается заново ≤5 с, старый токен даёт 403.
12. Домен: `https://windowshelper.win` → 200.

## 8. Эксплуатация

1. **Вход:** Ctrl+Shift+A (или `▸ админ`) → админ-PIN `9111` → **сразу смените его** в разделе
   PIN-КОДЫ (и сайтовый `1212` тоже — друзьям его знать больше не нужно).
2. **Отключить сайт:** раздел САЙТ → снять галку, приписать текст для посетителей → СОХРАНИТЬ.
   У себя панель остаётся. Включить — поставить галку обратно.
3. **Посетители при выключенном сайте** видят полноэкранный `J.A.R.V.I.S. // ОФЛАЙН` с вашим
   текстом; кнопка на нём ведёт в панель (для вас).
4. **Закрыть вход только друзьям, себе оставить:** раздел РЕЖИМЫ → снять «Гости через домен»
   (сами вы под localhost — работаете как обычно).
5. Настройки переживают перезапуск (`data/admin.json`); токен — нет (войти заново).

## 9. Ограничения и пути развития

* PIN-коды — не пароли уровня enterprise: 4–8 цифр, защищены rate-limitом, но не хешем
  (хранение открытым текстом в gitignored-файле). Путь развития: bcrypt + роли (operator/viewer).
* Нет журнала действий администратора отдельным файлом (сейчас общие 50 строк журнала).
* Перезапуск пишет лог в `/tmp/jarvis-server.log`; под Windows-сервисом лог лучше перевести
  в `data/`.
* Рассылка «привязана» к опросу метрик (2 с) — при желании 24/7-доставления логичен SSE.

## 10. Заключение

Реализована админ-панель с отдельным PIN-кодом и всеми запрошенными функциями:

* **отключение сайта для других пользователей** — посетители получают экран «офлайн»
  и код 503, администратор сохраняет полный доступ через собственный токен;
* **смена PIN-кода сайта** — в один клик из панели, без перезапуска, со сменой собственной
  сессии; **смена админ-PIN** — с подтверждением текущим кодом;
* дополнительные функции: сводка состояния, режимы гостей и ИИ, очистка данных, рассылка
  сообщений, перезапуск сервера, выход.

Защита построена на трёх уровнях (сайтовый PIN / админ-PIN / одноразовый токен), rate-limit
входа и изоляции секретов в gitignored-файле. Внедрено в v2.8, код и отчёт отправлены в
репозиторий.
